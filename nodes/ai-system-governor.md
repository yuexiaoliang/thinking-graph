# AI System Governor

## Current understanding

这是讨论中对一种复合型角色的暂定命名，不是已经确立的职业分类。它关注的问题是：当执行交给多个 AI Agent，谁把目标、任务分配、评价和最终决策连成一个可负责的整体？

原讨论提出 Define、Decompose、Delegate、Evaluate、Decide 五项能力。这里的独立价值不是给能力清单命名，而是研究这些能力组合后的职责与控制边界。

## Scope

[未来稀缺人才](/thoughts/future-talent/)讨论能力为何升值；本节点只讨论角色如何组织 AI 工作，以及哪些判断与责任不能因委派执行而一并消失。是否需要一个人兼具所有能力，尚未确定。

## Key reasoning

多 Agent 项目需要明确目标、分工、相互制约和反馈。这个角色不必亲自完成每个步骤，但需要决定谁来判断、依据什么判断、判断出错后如何处理。

其中 Evaluate 依赖[验证架构](/thoughts/verification-architecture/)提供可靠的检查与反馈机制；这个依赖不能用“人最后看一眼”替代。对于没有标准答案的取舍，原讨论仍把最终判断和承担结果作为关键问题。

## Source scope

[人才讨论](/conversations/conv-20260922-001/)：`第三类：AI 系统架构师`、`第五类：最终决策者`、`AI System Governor` 三处共同形成此角色假设。

## Open questions

- 与产品经理、技术架构师、项目经理和管理者的职责边界是什么？
- 哪些授权与责任应保留给人，哪些可委派给 Agent？
- 这是一种独立岗位，还是多个岗位共同承担的工作方式？

## Continue From Here

用一个具体项目研究目标、授权、验收和最终决策如何分工，再检验这个角色是否需要独立存在。
